# Step Goal Prompt

Target file: `human_goal_requirements.md`

Purpose: make the goal file the best controlling project contract possible.

Use the full requirements set, open questions, Git edit signals, AI-managed annotations, and human input/source signals to propose conceptual diffs for `human_goal_requirements.md`.

The goal file should clearly capture:

- project objective and desired decision, understanding, or output
- audience and intended use
- scope boundaries, inclusions, exclusions, geography, people, topics, entities, and time sensitivity
- major success criteria and quality bars
- major structural requirements that downstream inputs, wiki, articles, reports, and outputs must support
- important caveats, risks, assumptions, or unresolved choices that belong at the goal level

Do not duplicate detailed source acquisition rules better owned by `human_input_requirements.md`, or detailed deliverable formatting rules better owned by `human_output_requirements.md`. Instead, capture the goal-level directive that those files must support.

If the current input or output files contain salient directive information that belongs in the goal, integrate it cleanly into the proposed goal file.

The goal file is the nontechnical user's main control surface and project rudder. Important controlling concepts should live here: project scope, geographies, dates or time periods, audience, constraints, exclusions, success criteria, output strategy, major deliverables, and assumptions. If input or output requirements contain controlling concepts missing from the goal, propose bringing those concepts into the goal file.
