# do_propose_output_artifacts

Propose and write artifact specs for directed outputs that don't have HTML artifact specs yet.

This command is called by the build pipeline during Phase 5. Your job is to read each directed output's content, understand what kind of visualization would best present it, and write a tailored `.artifact.md` spec file for each one.

## Non-Interactive Runtime Contract

This is a web-triggered spec generation phase. Never ask for confirmation or wait for input. When a design decision is needed, make it — you are the designer.

## Instructions

### Step 1: Read the Context

The build pipeline has prepared the following context for you:

1. **Project brief** — The `project.md` file with goals, context, key questions, and constraints.
2. **Design identity** — The `human_design_identity.md` file with brand colors, fonts, and design tokens.
3. **Directed outputs needing specs** — A list of directed output files with their topic mappings and content previews.
4. **Existing artifact specs** — Specs that already exist (do not create duplicates).

### Step 2: Analyze Each Directed Output

For each directed output needing a spec:

1. **Read the full content** of the directed output file from `outputs_ai/`.
2. **Identify the content type** — Is it a strategy report? A comparison matrix? A risk analysis? A trend dashboard? A monitoring checklist?
3. **Identify the key data structures** — Tables, lists, metrics, comparisons, timelines, hierarchies, relationships.
4. **Determine the best visualization strategy** — What HTML layout and interactive elements would make this content most useful and impactful?

### Step 3: Write Artifact Specs

For each directed output, write a `.artifact.md` file to `artifacts/artifact_specs/` with this structure:

**Filename:** `output_{sanitized_name}.artifact.md` where `sanitized_name` is the output filename (without extension), lowercased, with non-alphanumeric characters replaced by underscores.

**Frontmatter (YAML):**
```yaml
---
name: Human-readable artifact name
format: html
lifecycle: manual
modelId: (use the modelId provided in the prompt)
sources:
  - outputs_ai/reports/the_output_file.md
  - outputs_ai/wiki/related_topic_wiki_page.md
autoGenerated: true
outputFile: outputs_ai/reports/the_output_file.md
---
```

**Sources list must include:**
- The directed output file itself (primary source)
- Wiki pages from the topics that map to this output (from the topic mapping provided)

**Body (prompt_body):** Write a detailed, output-specific specification with these sections:

#### Goal
One paragraph describing what the artifact should communicate and who it's for.

#### Information Architecture
3–5 named sections, ordered by importance (progressive disclosure). For each section, describe:
- What content it contains
- How it should be laid out (cards, table, grid, tabs, accordion, etc.)
- What data from the source it draws from

#### Visualizations
Specific visualization types for this output's data:
- What kind of chart/diagram/matrix for each data structure
- Whether to use inline SVG, Canvas, or a lightweight CDN library
- Color coding strategy aligned with the design identity

#### Design Direction
Layout-specific guidance:
- Single column vs. multi-column vs. dashboard grid
- Key interactive elements (filters, tabs, hover states, collapsible sections)
- Print-friendly considerations if applicable

### Step 4: Quality Checks

Before finishing, verify:
- [ ] Every directed output in the list has a corresponding `.artifact.md` file
- [ ] Each spec's `sources` includes the output file and its topic wiki pages
- [ ] Each spec's `outputFile` frontmatter matches the directed output path
- [ ] Each spec's prompt_body is specific to the output's content (not generic)
- [ ] Slug pattern is consistent: `output_{sanitized_name}`
- [ ] No spec duplicates an existing artifact spec

## Output

Write only the `.artifact.md` files. Do not modify any other files. Do not write any other output.
